Android Application Security Assessment: Beetlebug

Performed a controlled Android application assessment using static analysis, ADB-driven dynamic testing, storage inspection, and backend validation to identify eight security weaknesses.

View GitHub repository All projects
FocusWeb & Mobile Application Security
Evidence18 screenshots
RepositoryPublic on GitHub

Skills demonstrated

  • Mapped application resources, exported activities, embedded values, and backend URLs.
  • Pulled SQLite and Shared Preferences artifacts and verified plaintext sensitive data.
  • Monitored Logcat for credit-card and PII leakage.
  • Validated SQL injection, public Firebase access, and unauthenticated administrator activity invocation.
  • Assigned retrospective risk ratings and paired every finding with actionable remediation (see Findings Summary).

Tools used

  • JADX
  • ADB
  • Logcat
  • SQLite Browser
  • curl
  • jq
  • Android emulator

Findings Summary

Severities and remediations below were assigned retrospectively from the documented evidence using standard OWASP/CVSS-style judgment (Critical / High / Medium / Low). They were not part of the original lab write-up.

This assessment documents 8 security weaknesses, matching the objective count.

IDIssueOWASP categorySeverityFixEvidence
BB-01Folder-unlock PIN hardcoded in strings.xmlOWASP Mobile M1:2024 Improper Credential UsageHighDo not embed secrets in resources; derive or fetch unlock secrets from a protected server-side check; obfuscation alone is insufficient.Refs 1-3
BB-02Promo code hardcoded and discount enforced client-sideOWASP Mobile M7:2024 Insufficient Binary ProtectionsMediumValidate promo codes and pricing on the server; treat the client as untrusted.Refs 4-5
BB-03Username, password and flag stored in plaintext Shared PreferencesOWASP Mobile M9:2024 Insecure Data StorageHighUse the Android Keystore / EncryptedSharedPreferences; never store passwords in plaintext preferences.Refs 6-7
